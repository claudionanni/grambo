# SST Timeline Markers

## Overview

SST (State Snapshot Transfer) operations now appear as **orange markers** on the timeline, positioned at their actual start times.

## How It Works

**Data Flow:**
```
graa --sst --json <logs> → sst_sessions.json
                                 ↓
                        grav3 maps start_time → frame index
                                 ↓
                        Timeline markers at correct positions
```

**Dual Timeline Display:**
- **Frame Navigation Bar:** Navigate by frame index (bottom slider)
- **Natural Timeline:** SST markers positioned by actual timestamps (above frame bar)
  - Orange markers show SST start times
  - Click markers to jump to corresponding frame

## Implementation

### Backend (grav3)
- Loads `sst_sessions.json` generated by graa
- Maps each session's `start_time` to closest frame using `event.timestamp`
- Creates timeline markers with frame indices

### Frontend (templates/index.html)
- Renders SST markers from backend data
- Positions markers on natural timeline track
- Clickable markers for frame navigation

## Usage

```bash
# Run complete pipeline
./grax3 error.log

# grax3 automatically:
# 1. Runs: graa --sst --json → sst_sessions.json
# 2. Passes SST data to grav3
# 3. grav3 creates timeline markers
```

## Visual Indicators

| Track | Color | Meaning |
|-------|-------|---------|
| SST (top) | Orange (#ff5722) | SST operations |
| CLU | Red | Cluster issues |
| NOD | Orange | Node issues |
| COM | Purple | Component issues |

## Technical Notes

- SST markers use natural timestamps, not frame indices
- Timestamp matching handles format differences (space vs T separator)
- Falls back to closest frame if exact timestamp not found
